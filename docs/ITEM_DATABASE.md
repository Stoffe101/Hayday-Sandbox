# Item database

## Files

* `data/items/categories.json` — category ids, display names, Lucide icon, colour, order.
* `data/items/<section>.json` — `{"schema": "hayday-sandbox-items", "schema_version": 1, "items": [...]}`.
  Generated by `tools/catalog/build_catalog.py` from `data/research/items_research.json` +
  `data/research/item_overrides.json`. Edit the overrides (or the research) and regenerate rather than hand-editing
  generated files, so the provenance stays reproducible.
* `user://items/*.json` — optional user additions/overrides loaded after built-ins (same schema).

## Record

```json
{
  "id": "bakery",                    // stable snake_case slug; never reuse or change (use aliases)
  "name": "Bakery",
  "category": "production",
  "footprint": [3, 3],               // W×H tiles, or null when unknown
  "footprint_status": "confirmed",   // confirmed | community | approximation | unverified | unknown | original
  "provisional_footprint": [2, 2],   // only with footprint null: planning size, always flagged in the UI
  "unlock_level": 4,                 // null = unknown
  "cost": {"coins": 20, "diamonds": null, "other": null},   // null = unknown; never estimated
  "max_count": 1,                    // per farm; null = unlimited/unknown
  "flippable": true,                 // Hay Day "rotate" = mirror (swaps W×H)
  "movable": true, "placeable": true,// placeable=false → reference-only (fixed scenery)
  "connect": {"group": "fence", "style": "fence"},           // auto-connecting items
  "layer": "ground",                 // flat items (paths) draw beneath upright objects
  "season": "", "tags": [], "aliases": ["old_id"],
  "data_status": "community", "sources": ["https://…"], "notes": "…",
  "art": "bakery"                    // asset key, defaults to id
}
```

`ItemDef.from_dict` validates and reports problems without crashing; `ItemDatabase` rejects duplicate ids, warns
about unknown categories, and resolves aliases (`resolve_id`).

## Confidence model

| Status | Meaning | UI |
|---|---|---|
| confirmed | Stated by ≥2 consistent sources (e.g. English + Russian wiki infoboxes) | green badge |
| community | Single fan-wiki source | blue badge |
| approximation / unverified | Derived or weakly sourced (e.g. field 1×1 from old client data) | amber badge |
| unknown | No source; `provisional_footprint` used for planning | red "Size unknown" badge; Realistic Mode lists it |
| original | Editor-only items (planning markers) | — |

Unlock levels for most decorations are the wiki's default `1`, not a verified gate. ~1,458 decorations showed a
"999 diamonds" placeholder price meaning *not sold*; that is stored in `cost.other`, not as a price. Known source
disagreements (e.g. Bakery level 4 vs 2, Feed Mill 2 vs 3) are recorded in each item's `notes` and in
`docs/research/ITEM_DATA_RESEARCH.md`.

## Updating

1. Edit `data/research/item_overrides.json` (corrections, ids, provisional sizes, placeable/movable, aliases), or
   re-run the research extraction (script inlined in `docs/research/ITEM_DATA_RESEARCH.md`).
2. `python3 tools/catalog/build_catalog.py && python3 tools/art_generator/generate.py && python3 tools/catalog/coverage_report.py`
3. `godot --headless --path . --import && python3 tools/ci/validate_data.py` and the test suites.
