# Private original-art pack (personal use only)

Hayday Sandbox itself contains **no Supercell artwork**. Everything in this repository, in CI and in the released
Windows build is original placeholder art (CC0) generated by `tools/art_generator/`.

The user of this project states that Supercell support allowed them to obtain, extract and use **original Hay Day
art for personal use in this app**, on condition that it is **never redistributed**. That is the user's statement,
not something the project could verify. The project acts on it with strict limits: the art is collected and used
only on the user's own machines, as a *private asset pack*, and several independent safeguards keep it out of git,
CI and releases.

This page covers what the pack is, how it is obtained, where the files live, how to install it on Windows, and
the safety mechanisms.

## What the private pack is

* An ordinary asset pack in the format of [ASSET_PIPELINE.md](ASSET_PIPELINE.md) (`pack.json`, format
  `hayday-sandbox-asset-pack`). Its id is `hayday_original`.
* It is installed into the app's **user folder** (`user://asset_packs/hayday_original/`). User packs take
  priority over the built-in placeholders (priority 100 + pack priority). Items without original art keep their
  placeholder.
* Sprites are calibrated so that `anchor` is the texture pixel at the footprint's **ground centre**. One world tile
  is 64×32 px. Placement rules never depend on sprite pixels (AGENTS.md rule 4), so the pack changes how the farm
  looks, never what can be built.
* The app never downloads anything. The pack is built by the scripts in `tools/private_assets/` on your machine.

## Where the files live

| What | Linux (dev box) | Windows |
|---|---|---|
| Private storage root (`<root>`) | `/root/hayday-sandbox-private-assets` (or `~/hayday-sandbox-private-assets`, or `$HAYDAY_PRIVATE_ASSETS`) | `%USERPROFILE%\hayday-sandbox-private-assets` |
| Raw downloads + indexes | `<root>/raw/fankit/`, `raw/wiki/`, `raw/wiki_ru/` (`files/`, `index.json`, `failed.json`, logs) | same, under `<root>` |
| Client-file extraction (optional) | `<root>/raw/apk_extracted/`, `raw/apk_sprites/<version>/` | same |
| Built pack(s) | `<root>/packs/<id>/` (written by `build_pack.py`; may include `hashes.json`) | same |
| **Installed pack (what the app reads)** | `~/.local/share/HaydaySandbox/asset_packs/hayday_original/` | `%APPDATA%\HaydaySandbox\asset_packs\hayday_original\` |
| Acquisition state, logs, Python venv | `<root>/acquire_state.json`, `<root>/logs/`, `<root>/.venv/` | same |
| Leak-guard cache (hashes of private images) | `<root>/.leakcheck/` | same |
| Screenshots or QA images that show original art | under `<root>` only (e.g. `<root>/screens/`) | same |

None of these folders may be inside a git work tree. `fetch_fankit.py`, `fetch_wiki.py`, `extract_from_apk.py`,
`acquire.py`, `install_pack.py` and `Acquire-HaydayAssets.ps1` refuse such a destination.

## How it is obtained

| Route | Tool | What it does |
|---|---|---|
| Supercell **Fan Kit** | `tools/private_assets/fetch_fankit.py --out <root>` | Supercell's public, unauthenticated Fan Kit portal (fankit.supercell.com, project 361). Lists every asset through the portal's search API and downloads the original files through the portal's own download endpoint. Download tokens are used in memory only, never stored. Each file is checked (HTTP status, type, decodes, dimensions) and SHA-256 hashed into `raw/fankit/index.json`. |
| **Hay Day Wiki** (Fandom), en + ru | `tools/private_assets/fetch_wiki.py --out <root> --wiki en\|ru --resume` | Public MediaWiki API plus the wiki's static image CDN (`format=original`). Each file is verified against the API's SHA-1. Discovery uses object categories plus the catalogue's item names and cited pages. |
| Game client files **you already have** (optional) | `tools/private_assets/extract_from_apk.py extract <apk/xapk> --out <root>` | Verifies the APK signature is Supercell's, then decodes the `.sc`/`.sctx` files and renders sprites locally. It never downloads anything and never contacts a server. Details: [research/ASSET_ACQUISITION.md](research/ASSET_ACQUISITION.md). |
| Pack build | `tools/private_assets/build_pack.py --root <root> --install-dir <dir>` | Matches images to catalogue items, calibrates anchors and scale, and writes and installs the pack. This tool is maintained separately. `acquire.py` reads its options and imports at run time. |

`tools/private_assets/acquire.py` runs these steps in order with resume (details below). On the development
machine on 2026-11-09 the indexes record 2,808 of 2,808 Fan Kit assets downloaded (0 failed), 2,386 en-wiki files
and 1,519 ru-wiki files: about 1.1 GB, 0.74 GB and 0.62 GB on disk.

**Hard limits** (built into the tools):

* public endpoints only; no logins, no accounts, no personal account data;
* bot protection (Cloudflare "Just a moment", Turnstile, CAPTCHA) is **never bypassed**. A source that answers with a
  challenge is recorded as blocked and skipped;
* **no Supercell game servers**, no emulation of the game client protocol;
* polite traffic: at most 3 concurrent requests, delays between requests, exponential backoff that honours
  `Retry-After`, and resume, so a re-run does not download verified files again.

**No redistribution.** Never commit, push, upload, attach, share or publish the raw files, the pack, a pack zip, or a
screenshot that shows original art. That includes GitHub issues, CI artifacts, releases, chats and cloud drives
shared with others. A pack zip handed to you from a session is for your own computer only.

## Installing on Windows

### Option A: a pack zip you were given (fastest)

If a pack zip was prepared for you privately, for example a file from your session such as
`hayday_original.hdpack.zip` (never via git or CI), use any one of these:

1. **In the app:** Settings → *Install asset pack (.zip)…* (also in the Asset Manager, Ctrl+Shift+A), then choose
   the zip.
2. **Command line, app:** `HaydaySandbox.exe -- --install-pack=C:\path\hayday_original.hdpack.zip --quit-after-install`
   (prints `INSTALL-PACK …`; exit code 0 = installed).
3. **Command line, Python** (from a source checkout):
   `py tools\private_assets\install_pack.py C:\path\hayday_original.hdpack.zip`. It validates `pack.json`, skips
   unsafe zip entries, installs atomically into `%APPDATA%\HaydaySandbox\asset_packs\<id>\`, keeps your
   `overrides.json` and refuses any destination inside a git work tree.

Restart the app (or re-open the Asset Manager). The pack shows under **Packs**, and items with original art are
marked *Original art*.

### Option B: one command that rebuilds everything

Requirements: Windows 10/11, internet access, about 3 GB free disk space for the Fan Kit and wiki downloads, and
Python 3.10+ (the script finds it, or installs it with winget when you pass `-InstallPython`).

1. Get the source (clone it, or download and unzip it from GitHub).
2. Double-click `tools\private_assets\acquire_windows.bat`, or run in PowerShell:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File tools\private_assets\Acquire-HaydayAssets.ps1
   ```

   The script:
   * finds Python (`py` launcher → `python` → default install folders), or prints the winget command;
   * creates a virtual environment in `%USERPROFILE%\hayday-sandbox-private-assets\.venv`;
   * runs `acquire.py`, which installs Pillow, numpy and requests plus whatever the step scripts import (read
     from their source), then runs Fan Kit → wiki (en) → wiki (ru) → [APK, only with `-Apk`] → build+install;
   * prints a summary with per-step status, counts, the install folder and the log folder.
3. Start Hayday Sandbox.

Useful options: `-DryRun` (show the plan), `-Steps build` (rebuild and reinstall the pack only), `-Refresh`
(re-check the sources for new files), `-Apk D:\phone\hayday.xapk` (also extract from a client file you already
have), `-Root` / `-InstallDir`, and anything after `--` goes to `acquire.py` unchanged. **Re-running the same
command resumes.** State is kept in `<root>\acquire_state.json`, finished steps are skipped, and the fetchers keep
verified files and continue partial downloads. On Linux/macOS run `python3 tools/private_assets/acquire.py`
(add `--venv` if your system Python refuses pip installs).

## Safety mechanisms

| Layer | What it does |
|---|---|
| Storage outside the repository | Every tool that writes art refuses a destination inside a git work tree. |
| `.gitignore` | `hayday-sandbox-private-assets/`, `asset_packs/`, `hayday_original/`, `*.hdpack.zip`, `*.xapk`, `*.apk`, `*.pck`, `private/`, `assets/original/*`, game formats. |
| Leak guard: `tools/ci/check_private_leaks.py` | Fails on: images/audio/video outside `assets/placeholders/items/`, `assets/ui/`, `docs/screenshots/`; archives and game/package formats (`.zip .xapk .apk .obb .sc .sctx .ktx .zktx .pck …`); files whose bytes are media although the extension says otherwise; paths containing `private-assets`, `hayday_original`, `raw/fankit`, `raw/wiki` or an `asset_packs/` folder; images named like official art (`hayday_` prefix, `fankit`, `supercell`); files > 5 MB; Fan Kit download tokens, signed or bulk `media.ffycdn.net` URLs, private index files; **any file identical (SHA-256/SHA-1) to a file in the private storage**. That last check uses `<root>/raw/**/index.json`, `<root>/packs/**/hashes.json` and a cached hash of every image under `<root>` and the installed pack, plus every other file of 64 B to 5 MB under `<root>/raw/`, `packs/`, `mapping/`, `dashboard/` and the installed pack (game data CSVs, fonts, indexes, pack manifests, mapping DBs; generic LICENSE/README/NOTICE files excepted). Text files are compared too. It only runs where private storage exists, never in CI. Modes: whole tracked tree (default), `--staged`, `--range`, `--rev`, `--paths [--artifact]`, `--self-test`. |
| Git hooks: `tools/git-hooks/` | `pre-commit` checks the staged blobs. `pre-push` checks every file version in the commits being pushed, which catches `--no-verify` commits. Both fail closed when Python is missing. Install once per clone with `tools/ci/install_git_hooks.sh` (Git Bash on Windows works), or `git config core.hooksPath tools/git-hooks`. |
| CI (`.github/workflows/ci.yml`) | *validate*: the guard's self-tests, the whole tracked tree, and every commit of the push or PR. *visual*: fails if `assets/original/` or a user `asset_packs` folder has content; screenshots are rendered with an empty, isolated user-data folder (placeholders only) and checked before upload; only `artifacts/screens/` is uploaded. *windows-build*: export presets exclude `assets/original/`, `asset_packs/`, `*hayday_original*`, `private/`; after export (also inside `tools/build/build.sh`, which deletes the bundle zip if the check fails) `tools/ci/check_export_contents.py` reads the PCK file lists inside the `.exe` and the Linux binary (and the bundle zip) and fails on any private path or on imported media from outside the public art folders; only the verified zip is uploaded. |
| Test runners | `tools/ci/visual_tests.sh` (temporary `XDG_DATA_HOME`) and the Windows runners `tools\ci\windows_checks.ps1` / `visual_tests.ps1` (temporary `APPDATA` per Godot child) never load the user's installed packs, so test logs and screenshots show placeholders or synthetic packs only. |
| App | Packs live in the user folder and are never part of the export; `res://assets/original/` is git-ignored and excluded from exports. |

If the guard blocks a commit, unstage the file (`git restore --staged -- <path>`) and move it into `<root>`. If it
is a genuine false positive, change the rule in `check_private_leaks.py` together with a case in its `--self-test`.
Do not bypass the hooks for art. If private art was ever pushed, deleting the file is not enough: rewrite the
history (e.g. `git filter-repo`) and force-push before anyone else fetches.

## Screenshots, docs and CI use placeholders only

* `docs/screenshots/` and the CI screenshot artifacts are produced by `tools/ci/visual_tests.sh`. It gives every
  run a fresh, empty user-data folder, so a private pack in `user://asset_packs` can never appear in them.
  `assets/original/` must stay empty in git.
* On Windows, `tools\ci\visual_tests.ps1` and `tools\ci\windows_checks.ps1` do the same: every Godot child gets a
  fresh temporary `APPDATA`, so `%APPDATA%\HaydaySandbox\asset_packs\hayday_original\` is never loaded and private
  art can't appear in public screenshots or test runs. The temporary folder is deleted afterwards.
  `windows_checks.ps1` also refuses to import when `hayday-sandbox-private-assets` is inside the repository, and
  runs the leak guard and its self-test as part of every check run.
* Screenshots made *with* the private pack (QA, comparison) belong under `<root>` and nowhere else. The leak guard's
  hash check flags such a file if it is copied into the repository.
* CI machines never have the private storage. Uploaded artifacts are limited to test logs, `artifacts/screens/`
  (placeholder screenshots, checked before upload) and the verified Windows zip.

## Checking the pack in the real app (private QA)

All of these write only to `<root>` (they refuse the repository) and contain no art:

* `godot --path . -- --selftest=artcheck` — for every catalogue item: does it resolve to `hayday_original` and does
  its texture load; variants, connection pieces, thumbnails, texture memory. Counts go to
  `<root>/mapping/godot_artcheck.json`. Run it under Xvfb with `--rendering-driver opengl3` for real texture memory.
* `godot --path . -- --selftest=artflow` — editor workflows with the pack (open the QA layout, catalogue
  thumbnails, place, drag, undo/redo, fence line, variant, save/load, panning) with timings.
* `godot --headless --path . --script res://tools/private_assets/make_test_layout.gd` — the QA layout
  (`<root>/layouts/real_art_test.hdlayout`, ids only); `-- --gallery=production+animal_home` or `-- --items=a+b`
  build item galleries.
* `tools/private_assets/render_real_art.sh [scenarios] [WxH:scale ...]` — Xvfb screenshots of the real app with the
  pack into `<root>/screens` (`--real-art`, `at_<x>_<y>_<zoom>`, `export2x`, `export_objects`, `--dump-objects`,
  `--hide-panels` in `tests/visual/capture.gd`), then `tools/private_assets/annotate_screens.py` draws footprint
  diamonds, ground-centre crosses and labels on them for checking the calibration by eye.
* Items checked that way are listed in `<root>/mapping/visually_verified.json` and marked `verified` in the
  installed pack's `overrides.json` (which `build_pack.py` keeps and counts).

## For contributors and AI agents

* Private art, private indexes (which may hold CDN URLs), processed sprites, pack zips and screenshots that show
  original art go **only** to `<root>` or the app's user folder. Never `git add` anything from there, and never print
  image bytes to logs.
* Run `tools/ci/install_git_hooks.sh` once per clone. Before pushing, `python3 tools/ci/check_private_leaks.py`
  (add `--include-untracked` for a pre-flight of new files) must pass.
* Tools you write must not embed art and must default their output to the private root.
